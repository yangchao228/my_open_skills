# 文章转口播稿（article-to-koubo）

把一篇写给眼睛看的文章，变成一段说给耳朵听的话：像一个人在跟朋友聊天，轻松、好懂，偶尔让人笑一下。

## 什么叫"活人感"

| 活人 | AI 味 |
| --- | --- |
| 对着一个人说话，"你""我"很多 | 对着"大家"讲，满嘴"我们" |
| 有态度：敢说"我觉得""这个我不太信" | 四平八稳，最后来一句"凡事都有两面性" |
| 有起伏：长句短句交替，情绪有来由 | 每句一样长，情绪靠"震撼""炸裂"喊 |
| 听得懂：先讲事再给名字，数字少而圆 | 术语一串，定义套定义，数字精确到小数点 |
| 偶尔好笑：自嘲、反转、一句大实话 | 要么一本正经，要么硬塞烂梗 |
| 只说原文有的事 | 编细节、编经历，替听众总结意义 |

## 输入和默认值

只有在缺少文章，或者缺少会改变写法的关键信息时，才问一轮问题，而且只问一次。其余情况直接用默认值，并在改稿说明里写清楚用了哪些默认值。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 文章 | 必填 | 正文、链接内容或笔记都行 |
| 平台和时长 | 短视频，约 3 分钟 | 用语速换算字数，默认 4 字/秒，约 240 字/分钟 |
| 出镜方式 | 真人出镜 | 配音或数字人时，数字写成汉字读法，不用"嗯""呃"，并标注多音字 |
| 听众 | 聪明但不懂行的普通人 | 决定术语留多少 |
| 幽默浓度 | 中（偶尔） | 低、中、高，剂量见 [humor-and-emotion.md](references/humor-and-emotion.md) |
| 情绪浓度 | 中 | 同上 |
| 说话样本 | 无 | 用户以前的口播逐字稿，用来做人设卡 |

## 工作流

### 第 0 步：人设卡（可选）

用户提供了过去的口播逐字稿，或者说明了自己的说话习惯时，先提炼一张人设卡：

```md
## 口播人设卡
- 怎么称呼听众：（你／朋友们／兄弟们……）
- 口头禅：（最多 3 个，可以用 --allow 放行）
- 句子偏长还是偏短：
- 幽默风格：（自嘲／吐槽／冷幽默……）
- 绝对不说的词：
- 开场和收尾习惯：
```

人设卡保存在用户自己的工作目录，不要写进这个 skill 的目录。没有样本就用默认风格：轻松聊天型，对着"你"说话。

### 第 1 步：拆文，产出口播骨架

先不写稿，输出骨架：

```md
## 口播骨架
- 一句话核心：（听众只记得住一句话的话，记哪句）
- 开头钩子：（反常识的事实／具体画面／一个真问题／一句大实话，任选一种）
- 要点：（最多 3 个，短视频 2 个就够；每个配一个例子、比喻或数字）
- 情绪高点放在哪：（放在哪个事实后面）
- 术语处理：术语 → 删／换／留（见 jargon-translation.md）
- 删掉的内容：……（原因：太细／听众用不上／时长不够）
- 原文作者的立场：（口播要保留的态度）
```

原文要点比骨架多是正常的。口播讲不全，挑最能打的讲透。

### 第 2 步：复述起稿

**把原文放一边**，照着骨架讲给一个具体的人听。默认讲给"一个聪明但不懂行的朋友，在饭桌上"。不要逐段改写原文。

结构：

1. **钩子**（前 3–5 秒）：必须出现跟主题相关的具体东西。
2. **跟你有什么关系**：一两句，把听众拉进来。
3. **要点**：2–3 个。每个要点的写法是：大白话结论，加一个例子或比喻，可以再加一处情绪或幽默。
4. **收尾**：回扣开头的画面或比喻，再给一个具体的动作或一句大实话。互动可以有，但要具体。

写的时候守住这些：

- 多说"你"和"我"，少说"我们"和"大家"。
- 两个停顿之间不超过 20 字左右，长句和短句交替，每段至少一个短句。
- 术语先讲事、再给名字；全稿英文词不超过 3 个；数字少而圆。
- 幽默和情绪按剂量放，手法见 [humor-and-emotion.md](references/humor-and-emotion.md)。情绪前面必须有事实引出来，两个笑点之间至少隔一个信息点。
- 至少有一处明确的态度，比如"我的建议是""这个我不太信"。态度要来自原文作者，或者由用户确认过。
- 正文只用，。？！……这几种标点；不用括号、破折号、列表、Markdown。
- 写法参考 [spoken-style.md](references/spoken-style.md)，改法参考 [before-after.md](references/before-after.md)。

### 第 3 步：体检

把口播正文（不含改稿说明）存成纯文本文件，放在用户的工作目录或临时目录，不要写进这个 skill 的目录。然后运行：

```bash
python3 <本 skill 目录>/scripts/koubo_lint.py <稿件.txt> --target-seconds <秒数> [--terms "术语1,术语2"] [--allow "口头禅"] [--delivery tts]
```

`<本 skill 目录>` 指这份 SKILL.md 所在的文件夹，要写成绝对路径。运行时的当前目录通常是用户的项目目录，直接写 `scripts/koubo_lint.py` 会找不到文件。

- **必须改**：全部改掉。退出码为 1 时表示还有必须改的项。
- **建议改**：逐条判断。已经通顺自然的可以保留，在说明里写一句为什么保留。
- **提示**：看一眼，比如数字读法、英文词。
- 修改时**重写整句**，不要机械替换。比如把"首先"换成"第一点"，等于没改。
- 最多体检 2 轮。2 轮后还剩的项，原样写进交付说明，不要无限循环。

脚本只检查能量化的部分。各类问题的完整清单见 [ai-flavor-blacklist.md](references/ai-flavor-blacklist.md)，第二部分要靠自己判断。

### 第 4 步：出声检查和五维自评

在心里从头到尾念一遍：

- 每句话能不能一口气说完？
- 代词会不会听混？隔两句以上就重新点名。
- 数字和英文的读法确定了吗？有没有同音词或多音字？
- 幽默和情绪各放了几处，是否符合剂量？有没有笑点挨着严肃信息？
- 有没有原文里没有的事实、数字、经历？

然后按五个维度打分，每项 1–5 分：

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 像人在说 | 像念文章 | 偶尔有念稿感 | 像在跟朋友聊天 |
| 听得懂 | 术语成堆 | 个别地方要想一下 | 没有一处要停下来想 |
| 轻松 | 端着或者硬凹 | 有轻松的地方但不自然 | 笑点和情绪自然，有来由 |
| 节奏 | 句句一样长 | 有变化但偏平 | 长短交替，有起伏有回扣 |
| 忠实 | 编了事实或经历 | 有夸大的嫌疑 | 只说原文有的，夸张一听就是夸张 |

总分低于 20，或者任何一项低于 3，就回到第 2 步重写有问题的部分。"忠实"必须是 5 分，不到 5 分不能交付。

### 第 5 步：交付

```md
## 口播稿
<纯文本，可以直接念；需要用户补充的地方写 [[待补：…]]>

## 提词器版（用户要求时才给）
<一口气一行；需要停顿的地方空一行；重音词加粗。这个版本不进体检>

## 改稿说明
- 一句话核心：
- 参数：平台／目标时长／出镜方式／幽默浓度／情绪浓度（标注哪些是默认值）
- 删掉了什么：……（原因）
- 术语处理：术语 → 怎么处理
- 幽默点：第几段「……」，用的什么手法
- 情绪点：第几段「……」，由哪个事实引出
- 待你补充：[[待补]] 共几处，分别是什么
- 待核实：事实／读音／多音字
- 体检：必须改 0｜建议改剩几项（保留原因）｜约多少字，约多少秒
- 五维自评：像人在说 x/5，听得懂 x/5，轻松 x/5，节奏 x/5，忠实 x/5
```

## 风格卡（可选）

风格卡用来让口播**像某位博主**，也可以像用户自己。它记录对方的说话方式：句长、节奏、语速、口头语、开头和结尾套路、讲故事的结构、金句的写法和位置、情绪怎么推进。

**优先级**：人设卡 > 风格卡 > 默认风格。用户点名某种风格时启用对应的风格卡。用户也可以在人设卡里写明默认用哪张。

**怎么做一张风格卡**

1. 收集 3–5 份逐字稿。优先用带时间戳的 `.srt` 或 `.vtt` 字幕，这样才能算出真实语速。
2. 生成骨架：

   ```bash
   python3 <本 skill 目录>/scripts/build_style_card.py 稿1.srt 稿2.srt 稿3.srt --name "风格名" --slug 标识 -o 风格卡.md
   ```

   骨架里有这些内容：数值区间（一个 json 代码块）、逐篇统计、体检在真人稿上的误报、可能需要放行的词、高频口头语。
3. 看过原视频后，人工补全"待人工填写"的定性部分。每条写成"他怎么做 → 为什么有效 → 你怎么用"，配上自己写的示例，不贴原句。
4. 逐字稿原文只用来分析，不放进 skill 目录，也不提交进仓库。

**启用风格卡时**

- 第 2 步起稿按风格卡的手法和剂量来写。风格卡里写明的"覆盖默认规则的地方"，比如金句额度、情绪浓度，以风格卡为准。
- 第 3 步体检加上 `--style-card <风格卡路径>`。报告会多出一段"像不像"小结，偏离区间的项报为建议改。
- 第 4 步五维自评之外，再加一项"像不像"，按 1–5 分打。
- 交付的改稿说明里加两项："像不像"小结，以及风格手法标注，写清哪一句用了对方的哪个手法，方便用户边用边学。

**底线不变，风格卡不能突破**

- 不冒充本人：不用对方的名字、身份、经历，不用对方标志性的自我介绍和结束语。
- 不照搬对方的原句和原稿。
- 不编事实、不编经历：故事位置换成用户自己的经历，用户没提供时写成 `[[待补]]`。
- 紧迫感可以学，但必须有原文事实撑着；体检的"空洞恐吓"类别会提醒。

## 其他模式

- **只体检**：用户给的是现成的口播稿，只想看问题时，跑第 3 步的脚本，再加上第 4 步的判断，输出问题清单和修改示范，示范最多 5 处。不重写全文。
- **按反馈改稿**：只改用户指出的地方，以及因此必须连带修改的上下文。改完再跑一次体检，告诉用户改了哪几处。不要趁机重写全稿。

## 边界

- 不新增原文没有的事实、数字、引语和结论。比喻和夸张必须一听就知道不是事实。
- 不编造第一人称经历。只有原文作者写过、或者用户提供过的经历可以用；否则写成 `[[待补：你自己类似的经历]]`。
- 原文的限定条件不能丢，比如"可能""部分""在某场景下"。健康、金融、法律类内容尤其要注意，不能让口播比原文说得更绝对。
- 幽默不拿具体的人或群体开涮，不用网络烂梗，人设卡允许的除外。
- 不负责拍摄、配音生成、剪辑和发布。用户要这些时，说明这个 skill 只交付稿子。
- 原文的事实本身有问题时，指出来，交给用户决定，不要自己悄悄改掉。

## 安装与调用

把整个 `article-to-koubo` 文件夹复制或链接到运行时读取 skills 的目录，比如 Codex 或 Claude Code 的 skills 目录。要整个文件夹一起放，`references/` 和 `scripts/` 都不能少。

- Codex：用 `$article-to-koubo` 调用，或者直接说"把这篇文章改成口播稿"。`agents/openai.yaml` 提供了显示名和默认提示词。
- Claude Code：用 `/article-to-koubo` 调用，或者直接描述需求。
- 体检脚本只需要 Python 3，不用装任何依赖。
