# 术语翻译

听众听不懂，八成是因为术语。每个术语只有三种处理方式。

## 三选一

| 处理 | 什么时候用 | 怎么做 |
| --- | --- | --- |
| **删** | 听众不知道这个名字，也不影响理解 | 直接删，只讲它带来的结果 |
| **换** | 名字不重要，但它指的那件事重要 | 换成大白话，必要时配一个比喻 |
| **留** | 术语就是主题本身，或者听众以后还会碰到 | 先讲它干什么，再给名字；只解释一次，之后一直用同一个叫法 |

默认先考虑删，删不了再换，换不了才留。一条短视频里需要"留"的术语，最好不超过 2 个。

## 顺序：先讲事，再给名字

AI 爱用定义式："RAG，也就是检索增强生成，是指……"。听众刚听到一个陌生词，又紧跟着一串更陌生的词。

改成先讲事，最后给名字：

> 它回答之前，先去文件里翻，翻到相关的那几段，再照着答。翻书这一步，就是你可能听过的 RAG。名字挺唬人，干的就是这个事。

## 比喻怎么找

1. **用一个动词说清楚它在干什么**。比如缓存的核心动作是"把常用的东西放手边"。
2. **在听众的日常生活里找同一个动作**：厨房、通勤、点外卖、搬家、考试、带孩子、整理衣柜。
3. **补一句哪里不像**，免得误导听众："当然它比这个复杂，但意思差不多。"

比喻的雷区：

- 比喻比原概念还难懂。
- 一个概念用了三个比喻。
- 比喻会推出错误结论。比如把"相关"比喻成"导致"。

## 常见示例

| 术语 | 大白话或比喻 |
| --- | --- |
| 幻觉（AI） | 它不知道，但它不好意思说不知道 |
| RAG／检索增强 | 开卷考试：先翻书，再答题 |
| 向量化 | 给每段话算个坐标，意思相近的离得近；口播里通常直接删 |
| API | 餐厅的点菜窗口：你不用进厨房，按菜单点就行 |
| 缓存 | 常用的东西放手边，不用每次去仓库拿 |
| 技术债 | 东西全塞进衣柜，门一关，看着干净，问题还在 |
| 误差累积 | 每一步都差一点点，走到最后差了一大截 |
| 边际成本 | 多做一份要多花的钱 |
| 复利 | 利滚利，钱自己生钱 |
| 长尾 | 单个不起眼，加起来一大片 |

## 黑话换人话

| 黑话 | 人话 |
| --- | --- |
| 赋能 | 帮……／让……能 |
| 抓手 | 下手的地方 |
| 闭环 | 从头到尾走通 |
| 底层逻辑 | 说到底是因为 |
| 颗粒度 | 细到什么程度 |
| 沉淀 | 攒下来 |
| 对齐 | 说好／统一一下 |
| 落地 | 真用起来 |
| 痛点 | 最烦人的地方 |
| 迭代 | 改一版 |
| 赛道 | 这块生意／这个行业 |
| 链路 | 流程／步骤 |
| 心智 | 印象／一想到……就想到 |
| 方法论 | 办法 |
| 降本增效 | 省钱，干得快 |

## 写进改稿说明

术语怎么处理的要列出来，方便用户检查有没有误伤：

```md
- 术语处理：
  - 向量化：删（听众不需要）
  - 幻觉：留，先讲现象再给名字
  - RAG：留，用"开卷考试"做比喻，只出现一次；读法待确认（逐个字母念还是念成一个词）
```
